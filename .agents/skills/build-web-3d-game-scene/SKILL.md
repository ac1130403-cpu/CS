# 建立網頁 3D 遊戲場景

## 適用範圍

以 3D 場景、關卡或美術修改為主要交付時，依本技能執行。若需求涵蓋整款網頁遊戲，`web-game-vibe-coding` 負責玩法與開發階段，本技能補充該階段涉及的 3D 場景工作。場景提示詞、設計與局部修改只需完成指定交付。

## 方向未定時引導使用者選擇

先讀取使用者已提供的需求與專案既有設定。只在未定選項會實質影響交付時進行下列引導。需求明確時直接交付。

1. **應用類型**。先問想做哪種網頁 3D 體驗。依需求提供第一人稱射擊（FPS）關卡、探索／解謎、平台跳躍或互動導覽等選項。完全沒有方向時，推薦小型第一人稱探索關卡，說明它能先驗證走動、碰撞與單一互動。已指名 FPS 時，將推薦聚焦在 FPS 場景。
2. **場景主題與規模**。根據上輪選擇，給三個有明確尺度的構想，包含一個可最快完成的起點。FPS 例子可用「廢墟巷弄與小廣場」、「廢棄工業倉庫」或「封閉車站大廳」。每項用一句說明玩家在哪裡開始、能看到或操作什麼。第一版可推薦一個主要空間、一條可走路線和一項可驗證的場景互動。
3. **美術風格**。讀取 [美術風格與範例](references/art-direction.md)，依場景與工期優先給三個合適選項，使用者想比較時再列全部。每個選項都標明技術難度，說明該場景會呈現的樣子、最費工的技術，以及對素材匹配或瀏覽器效能的影響。新手通常推薦低多邊形。想保留廢墟材質、願意花時間統一素材時，推薦風格化半寫實。可附一組預設光線與氣氛。
4. **補足交付內容**。若尚未清楚，詢問要「可複製的提示詞」、「場景設計」或「直接實作」。視角、控制方式、裝置、素材偏好和驗收互動僅在會影響交付時補問。第一人稱桌面網頁可先採 WASD、滑鼠轉向、Esc 釋放滑鼠。

每輪只問當前的一個主要決定，給有編號的選項、一個推薦及可自行填寫的空間。當使用者說「沒想法」時，簡述目前推薦及原因，讓使用者可回「用推薦」或改選其他方向。若使用者授權「全部幫我選」，採用適合其目標的整組設定，整理完就依其交付要求繼續。保留已明確提供的答案，從第一個未定的步驟接續。範例對話見 [引導對話範例](references/guided-examples.md)。

收齊必要選擇後，用幾行摘要說明應用、場景、風格難度、預期操作與交付物。直接依使用者選擇交付。實作時沿用專案現有工具、控制方式與資料結構。新專案未指定堆疊時，從能完成需求的簡單 Three.js 設定開始。需要模組與資產打包，或使用者指定時，可採 Vite。使用 ES modules 或需要載入模型時，依專案設定提供本機 HTTP 啟動方式。

## 建立場景

1. 先做灰盒關卡。用 Three.js 基本幾何確認出生點、地板、牆、入口和玩家路線。完成需求中的一項互動，例如靠近公告欄按 E 顯示提示。既有遊戲的控制、相機和碰撞系統優先重用。
2. 需要輸出可重用的 GLB 時，可用 Three-Live 製作適合程式化的零件，例如可以調整寬度、缺口或材質的矮牆。保留可編輯的來源 JavaScript，將輸入參數集中，並以 Three-Live 支援的場景 API 建模。參考 [Three-Live 文件](https://github.com/google/three-live) 確認對應版本的匯出方式。CLI 命令格式為 `three-live-cli convert scene.js -o model.glb`。將匯出的 GLB 載入原本的 Three.js 主場景。
3. 對樹木、路燈、家具等適合重用的物件，視需要從 [ThreeJS Assets 免費區](https://threejsassets.com/assets?tier=free) 挑選素材。先看模型比例、輪廓、色彩和檔案大小能否配合場景，再依下方流程整合。高細節物件也可沿用使用者提供的 Blender 匯出 GLB。
4. 沿用專案的場景設定，集中記錄各模型的路徑、位置、旋轉與縮放。依遊戲規則配置簡化碰撞形狀，檢查牆、門、樓梯和障礙物更換外觀後的通行結果。裝飾物是否需要碰撞由關卡需求決定。
5. 在玩家視角調整材質、色彩和燈光。用輪廓、亮度與地標辨識入口及高度差。替換美術風格時，根據原始需求維持或調整路線與碰撞。

## 整合外部素材

- 確認個別素材頁的 Free 標示與[授權條款](https://threejsassets.com/license)。使用官方正式下載。把模型嵌入遊戲成品，避免將素材檔作為獨立下載品、素材包或公開模板散布。
- 使用 Three.js 的 `GLTFLoader`。素材若使用 Draco，配置 `DRACOLoader`，讓解碼器路徑配合部署的基底路徑。依模型實際使用的壓縮格式設定解碼器。參考 [GLTFLoader 文件](https://threejs.org/docs/pages/GLTFLoader.html)。
- 需要登入、無法下載或找不到合適素材時，先用相近比例的基本幾何完成場景，並保留替換位置及候選素材頁網址。CLI 無法完成匯出時，保留 Three-Live 來源腳本，在遊戲內暫用 Three.js 幾何，並如實說明未匯出的原因。
- 沿用專案現有的素材清單，記錄實際採用的外部素材名稱、來源頁、授權與用途。需要新建清單時可使用 `assets/ASSETS.md`。將只供後續參考的候選素材標清楚。

## 驗證與交付

- 用正常啟動方式在瀏覽器測試。從出生點走到指定位置，確認相機、路線、碰撞與互動符合需求。在第一人稱場景測試轉角、狹窄門洞、階梯及可辨識的地標。
- 檢查模型比例、朝向、接地與碰撞對齊。測試資產載入失敗時的替代物件。有建置流程時，執行正式建置，確認建置版能在目標基底路徑載入所使用的模型與解碼器。
- 交付啟動方式、操作方法、場景和素材來源、實際驗證項目與具體限制。依可用的執行環境說明瀏覽器或正式建置仍待驗證的部分。
